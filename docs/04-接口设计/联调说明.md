## 1. 本地联调环境

前端开发服务器：

```bash
npm run dev
```

Vite 代理：

```text
/portal -> http://localhost:8080
```

后端本地服务应保证 Portal 接口可通过前端相对路径访问，例如：

```text
http://localhost:5173/portal/api/site/config
```

## 2. 响应兼容规则

建议响应结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

当前 `src/api/portal.ts` 兼容：

- `code` 为 `0`
- `code` 为 `200`
- `code` 为 `"0"`
- `code` 为 `"200"`
- `code` 为 `"success"`
- 直接返回 `data` 本身

## 3. 错误处理与 Mock 兜底

| 场景 | 前端行为 | 后端排查方向 |
| --- | --- | --- |
| 返回 HTML | 抛出错误并使用本地兜底 | 检查代理、后端路由、登录拦截 |
| 返回非 JSON 文本 | 抛出错误并使用本地兜底 | 检查响应格式 |
| `code` 非成功 | 抛出错误并使用本地兜底 | 检查业务错误码和 message |
| 请求失败 | console.error 并使用本地兜底 | 检查服务、跨域、网络 |
| 字段缺失 | 过滤无效项或使用默认值 | 检查字段命名和必填规则 |

## 5. 线索提交接口

接口文档已确认：

```text
POST /portal/api/leads
```

请求字段：

```json
{
  "name": "",
  "company": "",
  "email": "",
  "phone": "",
  "demandDescription": ""
}
```

字段规则：

| 字段 | 规则 |
| --- | --- |
| `name` | 必填，最长 64 字符 |
| `company` | 必填，最长 128 字符 |
| `email` | 必填，最长 128 字符，需满足邮箱格式 |
| `phone` | 选填，最长 64 字符，仅允许电话白名单字符 |
| `demandDescription` | 选填，最长 1000 字符 |

响应字段：无业务数据，统一返回成功。

错误码：

| 错误码 | 说明 |
| --- | --- |
| `10001` | 请求参数缺失、格式不合法或长度超限 |
| `70007` | 同一 IP 触发线索提交限流 |
| `80000` | 系统内部异常 |

## 6. 联调顺序建议

1. 复测已接入的 5 个 Portal 接口。

5. 每接入一个接口，同步检查 API 字段映射和 Mock 兜底。
