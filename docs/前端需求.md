# 武汉云台数据有限公司官网前端需求文档

## 1. 文档说明

本文档用于说明“武汉云台数据有限公司官网”前端建设需求，面向前端开发、后端接口开发、产品确认和后续运营维护。

本项目目标不是一次性写死静态页面，而是建设一个可上线、可维护、后续可由后端/CMS 更新内容的公司官方网站。前端负责页面展示、交互、响应式适配、Mock 数据和接口对接能力；后端负责接口、数据库、内容管理和数据维护能力。

## 2. 项目目标

### 2.1 总体目标

建设武汉云台数据有限公司官网前台页面，展示公司品牌、产品能力、AI 战略、行业案例、企业实力、发展历程和联系方式，并为后续后端维护内容预留接口化能力。

### 2.2 阶段目标

当前阶段前端需要完成：

- 官网前台页面结构和视觉展示
- 首页核心模块完整展示
- 产品、案例、时间轴等内容数据化
- 联系我们表单前端交互和校验
- Mock 数据驱动页面展示
- API 层封装，方便后续替换真实后端接口
- PC、平板、移动端响应式适配
- 基础 SEO 信息
- 构建和部署能力

当前阶段不要求完成：

- 后端服务开发
- 数据库开发
- 后台管理系统完整 CRUD
- 登录权限系统
- 真实文件上传
- Excel 导出
- 后端缓存、队列、权限等能力

- 首页大量内容仍硬编码在 `Home.vue` 中，后端无法直接维护。

- 客户/案例图片使用外链图片，正式上线建议替换为公司真实素材或后台上传资源。

## 4. 前端建设原则

### 4.1 页面结构固定，内容数据化

前端负责页面结构、视觉、交互和展示逻辑。官网文案、产品、案例、时间轴、荣誉、客户、联系方式等内容应逐步从硬编码迁移为数据驱动。

目标结构：

```text
页面结构固定
内容来自 Mock/API
后端/CMS 维护内容
前端只负责渲染和交互
```

### 4.2 先 Mock，后接口

后端接口未完成前，前端使用 Mock 数据完成页面开发。Mock 数据字段应尽量与后端接口字段保持一致，避免后期大面积重构。

### 4.3 API 层隔离后端字段

页面组件不直接依赖后端原始字段。建议在 API 层或数据转换层完成字段适配，使组件内部字段稳定。

示例：

```text
后端字段 -> API 转换层 -> 页面组件字段
```

### 4.4 前端不直接操作数据库

前端不得连接数据库，不得出现数据库账号、密码、RDS 地址等敏感信息。所有动态数据必须通过后端接口获取。

### 7.2 环境变量

建议新增：

```env
VITE_USE_MOCK=true
VITE_API_BASE_URL=http://localhost:8080
```

规则：

- `VITE_USE_MOCK=true`：使用本地 Mock 数据
- `VITE_USE_MOCK=false`：调用真实后端接口

### 7.3 请求封装要求

需要封装统一请求模块：

```text
src/utils/request.js
```

请求封装需要支持：

- baseURL 配置
- 请求超时
- 统一错误处理
- 统一响应结构解析
- 后续 token 扩展能力

### 7.4 接口响应结构

建议后端统一响应结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

前端应处理：

- 成功状态
- 业务错误
- 网络错误
- 空数据
- 加载中状态

联系我们表单需要支持：

- 字段输入
- 必填校验
- 邮箱格式校验

- 提交 loading
- 防重复提交

接口化后，页面需要处理：

- loading：加载中

- 图片使用压缩资源
- 大图使用懒加载
- 不使用过重动画
- 构建产物过大时考虑路由懒加载
- 图标按需使用或保持可接受体积

当前构建产物存在 JS chunk 偏大的提示，后续可通过路由懒加载和代码分包优化。

如果项目后续需要更强类型约束，可迁移为：


## 16. 验收标准

### 16.1 页面验收

- 首页可以正常访问
- 顶部导航可跳转
- 首页各模块展示完整
- 产品列表展示正常
- 案例列表展示正常
- 关于我们内容展示正常
- 联系我们模块展示正常
- 移动端布局不崩

### 16.2 数据验收

- 页面主要内容来自 Mock/API 数据
- 修改 Mock 数据后页面展示同步变化
- 产品、案例、时间轴支持排序
- 无数据时有合理兜底展示

### 16.3 表单验收

- 必填项未填时有提示
- 邮箱格式错误时有提示
- 提交时有 loading 状态
- 提交成功有提示
- 提交失败有提示
- 表单提交字段与接口文档一致

### 16.4 联调验收

- `VITE_USE_MOCK=true` 时使用 Mock 数据
- `VITE_USE_MOCK=false` 时调用真实接口
- 后端接口返回成功时页面正常展示
- 后端接口异常时页面不崩溃

### 16.5 构建验收

- `npm install` 可安装依赖
- `npm run dev` 可启动开发环境
- `npm run build` 可完成生产构建
- `dist/` 可作为静态资源部署
