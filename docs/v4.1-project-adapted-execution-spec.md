# 武汉云台官网系统 v4.1 项目适配版执行规范

> 本文件是基于当前真实项目结构生成的执行规范。
> 它替代 v4 原稿中不匹配当前项目的路径、接口和认证假设。
> 执行目标是：保留现有官网前台，在同一个前端项目中新增 `/admin` 后台管理系统。

---

## 0. 最高原则

- 官网前台只负责展示数据。
- 后台管理只负责维护数据。
- 前台不得直接写数据。
- 后台不得混入前台展示逻辑。
- 前台展示数据来自 `/portal/api/**`。
- 后台维护数据走 `/admin/api/**`。
- 不使用 mock 数据作为最终数据源。
- 不为了接后台而重构现有官网 UI 结构。

---

## 0.1 AI 执行友好性规则

本规范用于指导 AI 分阶段执行。AI 不得一次性完成全部后台系统，必须按任务包推进。

AI 每次执行前必须先回答并确认：

```text
本次任务包编号：
本次允许修改文件：
本次禁止修改文件：
本次接入接口：
本次验收动作：
```

AI 每次执行后必须输出：

```text
已新增文件：
已修改文件：
已接入接口：
未完成项：
已执行验证：
风险或阻塞：
```

禁止行为：

```text
未确认任务包就跨模块开发
为省事跳过认证或 CSRF
用前端假数据代替真实接口
在一个任务里同时大改前台和后台
发现接口字段不确定时自行猜字段
```

字段、接口、认证方式不确定时，必须先只读检查后端 Controller、DTO、Request、Response、测试用例或接口文档，再继续执行。

## 5.5 Admin API 封装规则

后台接口封装必须集中在：

```text
src/admin/api/**
```

每个 API 文件必须只做三件事：

```text
定义当前模块请求函数
处理字段映射
返回 http 请求结果
```

不得在 API 文件中：

```text
写 UI 状态
写页面提示文案
写 mock fallback
直接操作 router
直接操作 localStorage 伪造登录
```

建议函数命名：

```text
adminLogin()
adminLogout()
getAdminMe()
getAdminCsrf()
uploadAdminMedia()
getAdminProducts()
createAdminProduct()
updateAdminProduct()
deleteAdminProduct()
sortAdminProducts()
```

## 5.6 通用响应结构处理规则

当前接口返回通常包含业务包装层，前端不得直接假设响应体就是业务数据。

API 封装层必须统一处理：

```text
HTTP 状态码
业务 code
业务 message/msg
业务 data
分页 records/list
空数组
空对象
```

建议处理逻辑：

```text
HTTP 2xx 且业务 code 为成功：返回 data
HTTP 401：跳转 /admin/login 或触发登录失效提示
HTTP 403：提示无权限
HTTP 400/422 或业务参数错误：展示后端返回的校验信息
HTTP 5xx：提示服务异常，不生成假数据
网络错误：提示网络异常，不静默失败
```

不得在页面中到处重复解析 `response.data.data`。业务包装层解析应集中在请求层或模块 API 层。

## 7.7 DTO 字段发现记录模板

每开发一个后台模块，必须先生成字段对应记录。该记录可以放在 AI 输出中，不要求写入代码仓库。

模板：

```text
模块名称：
后端 Controller：
后端 Request DTO：
后端 Response/VO：
列表接口：
详情接口：
创建接口：
更新接口：
删除接口：
排序接口：

字段对应表：
| 页面字段 | 控件类型 | 必填 | Admin 请求字段 | Admin 响应字段 | Portal 字段 | 校验规则 | 备注 |
|---|---|---:|---|---|---|---|---|
```

字段状态必须标明：

```text
confirmed     # 已由后端代码确认
derived       # 从前台映射或接口返回推导，需说明来源
unsupported   # 后端暂不支持，不得强行提交
unknown       # 未确认，必须暂停确认
```

AI 不得把 `derived` 或 `unknown` 字段当成已确认字段写入提交逻辑。

## 8. 认证与 CSRF 规则

当前 `src/api/http.ts` 已配置：

```text
withCredentials: true
```

后台认证应优先按以下模型实现：

```text
1. 进入 /admin
2. 调用 GET /admin/api/auth/me
3. 已登录：进入后台
4. 未登录：跳转 /admin/login
5. 登录前或写操作前获取 GET /admin/api/auth/csrf
6. POST/PUT/DELETE 请求按后端要求带 CSRF 信息
7. 退出调用 POST /admin/api/auth/logout
```

不得只在前端写一个假登录状态。

---

## 8.1 CSRF 接入细则

CSRF 具体字段名以 `GET /admin/api/auth/csrf` 返回值和后端安全配置为准。

执行时必须确认：

```text
CSRF token 返回字段名
CSRF header 名
登录接口是否需要 CSRF
logout 是否需要 CSRF
上传接口是否需要 CSRF
```

写请求统一经过一个辅助函数或统一拦截器携带 CSRF，不得在每个页面手写重复逻辑。

若 CSRF 过期：

```text
重新获取 CSRF
重试当前写请求一次
仍失败则提示用户重新登录
```

---

## 8.2 登录失效与权限错误规则

后台必须统一处理认证失败，不得每个页面各写一套。

统一行为：

```text
401 或未登录业务码：
  清理前端中的用户态缓存
  跳转 /admin/login
  保留 redirect 参数，登录后回到原页面

403 或无权限业务码：
  留在当前页
  显示无权限提示
  不清空登录态

CSRF 失败：
  重新获取 CSRF
  自动重试当前写请求一次
  第二次失败则提示重新登录
```

禁止：


## 14. 最终目标

最终上线后：

```text
/       → 官网前台，客户访问，只读展示
/admin  → 后台管理，管理员登录后维护内容
```

数据闭环：

```text
管理员在 /admin 修改内容
→ 后台调用 /admin/api/**
→ 数据写入数据库
→ 官网通过 /portal/api/** 读取
→ 客户看到最新官网内容
```

一句话：

```text
v4.1 = 按当前真实项目落地的前台只读 + 后台可写执行规范。
```
