# 前端字段与接口规范说明书

项目：武汉云台数据有限公司官网  
用途：前端维护、后端接口开发、数据库字段命名统一、接口联调、后续 CMS/招聘/AI 能力中心扩展。

> 本文档基于当前真实代码整理。当前项目暂无后端 API 调用、暂无 Mock 服务、暂无 Pinia/Store、暂无 TypeScript 类型定义。文档中标注为“建议字段”“后端待实现”的内容用于后续联调和动态化扩展，不代表当前页面已经实现。

## 4. 前端字段命名规范

### 4.1 前端建议命名

| 类型 | 命名方式 | 示例 |
|---|---|---|
| 普通字段 | camelCase | `companyName` |
| 数组字段 | 复数或 List 后缀 | `productList`、`cases` |
| 布尔字段 | is/has/can 前缀 | `isActive` |
| 图片字段 | `imageUrl` 或 `logoUrl` | `imageUrl` |
| 路由字段 | `detailUrl` | `/product` |
| 图标字段 | `icon` | `Network` |

### 4.2 后端/数据库建议命名

| 层级 | 命名方式 | 示例 |
|---|---|---|
| API JSON | camelCase | `companyName` |
| 数据库字段 | snake_case | `company_name` |
| 数据库表名 | snake_case 单数或业务名 | `product`、`contact_request` |

### 4.3 当前字段兼容建议

| 当前前端字段 | 建议 API 字段 | 建议数据库字段 | 说明 |
|---|---|---|---|
| `title` | `name` 或 `title` | `name/title` | 产品建议用 `name`，文章/案例建议用 `title` |
| `sub` | `subtitle` | `subtitle` | 产品副标题 |
| `desc` | `description` | `description` | 描述字段统一 |
| `img` | `imageUrl` | `image_url` | 图片字段统一 |
| `features` | `coreFunctions` | `product_feature` | 产品详情核心功能 |
| `quote` | `summary` 或 `quote` | `quote` | 案例总结/引用 |

## 17. 后续联调注意事项

1. 当前无 API 调用，接入后建议先封装请求层，例如 `src/api/home.js`、`src/api/products.js`。
2. 当前无 TypeScript 类型定义，如后续迁移 TS，建议先定义 `Product`、`CaseItem`、`ContactRequest`。
3. 当前产品字段 `title/sub/desc` 与后端常用命名不完全一致，建议接口层统一映射成 `name/subtitle/description`。
4. 当前案例字段 `img/desc` 建议统一为 `imageUrl/description`。
5. 当前联系表单没有 `v-model`、校验、提交逻辑。对接 `POST /api/contact` 前，需要补齐表单状态和校验。
6. 当前产品详情页和案例详情页是“汇总详情页”，不是单 ID 详情页。若后续需要单详情页，需要恢复 `/product/:id`、`/case/:id` 的详情渲染。
7. 当前 AI能力中心和公司招聘没有独立页面。接口可以先设计，但前端页面需要后续新增。
8. 当前客户 logo 使用 emoji，若后续进入 CMS，建议支持 `logoUrl` 图片字段，同时保留 `logoText` 兜底。
9. 当前导航滚动高亮依赖页面 section id，新增模块时需要同步更新 `SiteHeader.vue` 的 `navItems` 和 `sectionMap`。
10. 后端返回列表数据时建议提供 `sortOrder` 和 `isActive`，方便后台控制排序和上下架。
