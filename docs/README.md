# 武汉云台数据有限公司官网文档说明

本文档是 `docs` 目录的入口文件，用于帮助前端开发、后端开发、产品确认以及 AI 助手快速理解当前项目文档结构、阅读顺序、执行边界和当前优先任务。

## 1. 项目定位

本项目是“武汉云台数据有限公司官网”前端项目。

项目目标不是一次性静态页面，而是建设一个：

- 可上线
- 可维护
- 可由后端/CMS 更新内容
- 可逐步接入真实接口

的公司官方网站。

当前前端技术栈：

- Vue 3
- Vite
- Vue Router
- lucide-vue-next
- JavaScript
- CSS

当前暂不引入：

- TypeScript
- Pinia/Vuex
- 大型 UI 框架
- 前端直连数据库
- 后台管理系统完整 CRUD

## 5. 已知文档冲突与暂定规则

| 冲突项 | 当前情况 | 暂定规则 |

## 6. 当前项目状态

当前已实现：

- 首页 `/`
- 产品矩阵
- 产品详情汇总页 `/product`
- 案例详情汇总页 `/case`
- 关于我们模块
- 联系我们静态 UI
- 部分产品、案例、时间轴数据位于 `src/data/site.js`
- 生产构建可通过

当前未完成或待优化：

- 首页大量内容仍硬编码在 `Home.vue`
- 暂无统一 API 层
- 暂无独立 Mock 数据目录
- 暂无 `src/utils/request.js`
- 联系我们表单暂无字段绑定、校验和提交逻辑
- `/product/:id` 和 `/case/:id` 当前不是单详情页
- loading、empty、error 状态不足
- 图片加载失败兜底不足
- SEO、favicon、备案号、正式联系方式仍需补齐
- 外链图片需替换为正式资源或后台资源

## 8. AI 开发注意事项

AI 助手处理本项目时，请遵守以下规则：

- 修改代码前先阅读相关文档和现有代码。
- 优先沿用当前 Vue 3 + JavaScript + CSS 技术栈。
- 不要擅自引入 TypeScript、Pinia、Axios 或大型 UI 框架。
- 不要直接连接数据库。
- 不要把后端字段直接散落到页面组件中，应通过 API 层或数据转换层适配。
- 不要一次性大重构，优先小步推进。
- 不要删除用户已有代码，除非明确确认不再使用。
- 新增功能后需要保证 `npm run build` 可通过。
- 涉及字段、接口、阶段、任务状态或功能范围变更时，需要同步更新相关文档。

## 9. 接口统一约定

建议接口统一响应结构：

```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

当前暂定接口清单：

| 接口 | 用途 |
|---|---|
| `GET /api/site/config` | 获取站点配置 |
| `GET /api/home` | 获取首页内容 |
| `GET /api/products` | 获取产品列表 |
| `GET /api/products/:id` | 获取产品详情 |
| `GET /api/cases` | 获取案例列表 |
| `GET /api/cases/:id` | 获取案例详情 |
| `GET /api/about` | 获取关于我们内容 |
| `GET /api/contact/info` | 获取联系信息 |
| `POST /api/contact` | 提交联系表单 |
| `GET /api/jobs` | 获取招聘岗位，后续扩展 |

接口字段优先参考：

```text
docs/前端字段与接口规范说明书.md
```

如接口清单与旧文档不一致，暂以本文档的接口清单为准，并在后续同步修订相关文档。

## 11. 当前阶段完成定义

当前阶段完成应满足：

- 首页主要内容逐步由 Mock/API 数据驱动。
- 产品、案例、时间轴等字段命名趋于统一。
- 联系表单可输入、可校验、可模拟提交。
- 页面具备 loading、empty、error 兜底。
- 图片加载失败有基础兜底。
- 移动端布局稳定。
- `npm run build` 可通过。
- 代码状态与文档描述保持一致。
