# 武汉云台数据有限公司官网前端开发阶段

## 1. 文档说明

本文档用于拆解“武汉云台数据有限公司官网”前端项目的开发阶段，回答“分几步做、每一步交付什么、怎样判断完成”。

本文档基于当前项目代码和 `docs/前端需求.md` 编写，适用于前端开发推进、前后端联调排期、上线前检查和后续维护沟通。

当前项目技术栈为 Vue 3、Vite、Vue Router、lucide-vue-next、JavaScript 和 CSS。当前阶段不强制引入 TypeScript、Pinia/Vuex 或完整后台管理系统。

## 2. 当前项目定位

当前项目已经具备官网前台页面雏形，首页、产品汇总页、案例汇总页、关于我们模块、联系我们静态 UI 已经实现，`npm run build` 可构建通过。

从目标角度看，当前项目处于：

```text
第一阶段：静态官网页面完善  -> 基本完成，仍需收尾检查
第二阶段：数据化与 Mock 改造 -> 部分开始，尚未系统完成
```

当前最需要继续推进的是把首页硬编码内容逐步抽离为结构化数据，并补齐 Mock、API 层和联系表单能力。

## 4. 第一阶段：静态官网页面完善

### 4.1 阶段目标

完成官网前台的基础页面和主要展示模块，使项目具备可演示、可评审、可继续数据化改造的页面基础。

这一阶段重点不是接口，也不是 CMS，而是保证页面结构、视觉层级、导航跳转、响应式布局和基础构建能力稳定。

### 4.2 主要任务

- 完成首页 `/` 的核心模块展示，包括 Hero、AI 战略、产品体系、产品矩阵、创新研发、行业案例、关于我们、联系我们。
- 完成产品汇总页 `/product`，展示全部产品详情。
- 完成案例汇总页 `/case`，展示全部案例详情。
- 完成 Header、Footer、移动端导航和基础滚动跳转。
- 保证产品、案例、时间轴等已拆出的数据可以正常渲染。
- 检查 PC、平板、移动端布局，避免文字溢出、模块重叠、按钮不可点击。
- 保持 `npm run build` 可通过。

### 4.3 交付物

- 可访问的首页、产品汇总页和案例汇总页。
- 可复用的基础组件，例如 Header、Footer、标题组件、图标展示组件。
- 基础样式文件：
  - `src/assets/styles/global.css`
  - `src/assets/styles/home-hero.css`
- 路由配置：
  - `/`
  - `/product`
  - `/case`
- 一份可构建的前端静态产物 `dist/`。

### 4.4 验收标准

- 首页可以正常访问，首屏和主要模块展示完整。
- Header 导航可以跳转到页面或锚点。
- `/product` 可以展示产品详情内容。
- `/case` 可以展示案例详情内容。
- 移动端导航可展开、收起，点击菜单后体验正常。
- 主要模块在 1200px 以上、768px - 1199px、小于 768px 三类宽度下布局不崩。
- 运行 `npm run build` 可以完成生产构建。

### 4.5 当前状态判断

当前项目第一阶段已经基本完成，但仍建议做一次收尾检查：

- 检查移动端导航和锚点滚动体验。
- 检查首页长文案在窄屏下是否溢出。
- 检查外链图片加载失败时是否影响页面观感。
- 检查 Footer 中备案号、联系方式是否为正式信息。

## 5. 第二阶段：数据化与 Mock 改造

### 5.1 阶段目标

将官网主要内容从组件硬编码迁移为结构化数据，为后续 API 接入和后端/CMS 维护内容打基础。

这一阶段的目标是“页面结构固定，内容来自数据”。即使暂时没有真实后端，也要让前端先按接近接口的字段组织 Mock 数据。

### 5.2 主要任务

- 新增或拆分 `src/data` 下的数据文件，避免所有数据集中在一个文件中。
- 优先将 `Home.vue` 中的硬编码内容抽离到数据结构中。
- 将产品字段逐步从当前 `title/sub/desc/img` 形式映射为需求文档中的 `name/subtitle/description/imageUrl` 等规范字段。
- 将案例字段逐步从当前 `img/desc` 形式映射为 `imageUrl/description` 等规范字段。
- 为产品、案例、时间轴、指标等数据补齐 `sortOrder`、`isActive` 等后续维护字段。
- 页面渲染时按 `sortOrder` 排序，并过滤未启用数据。
- 为图片、图标、空数组数据准备基础兜底展示。
- 保持页面组件不直接关心后端字段变化，优先通过数据整理函数或 API 层适配。

### 5.3 建议目录

```text
src/
├── data/
│   ├── home.js
│   ├── products.js
│   ├── cases.js
│   ├── about.js
│   └── site.js
└── views/
```

如需保留当前 `src/data/site.js`，可以先采用渐进方式：

```text
先保留 site.js
逐步拆出 products.js、cases.js、home.js
最后让 site.js 只保留站点级配置或统一导出
```

### 5.4 交付物

- 独立 Mock 数据文件。
- 字段命名更接近接口规范的数据结构。
- 改造后的首页、产品页、案例页数据渲染逻辑。
- 数据排序、上下架过滤和基础兜底逻辑。
- 更新后的 `docs/前端字段与接口规范说明书.md` 或字段差异记录。

### 5.5 验收标准

- 修改 Mock 数据后，页面展示可以同步变化。
- 首页主要文案、指标、AI 能力、产品、案例、时间轴等内容不再大量硬编码在 `Home.vue`。
- 产品、案例、时间轴支持排序。
- `isActive: false` 的数据不会在页面展示。
- 产品和案例字段与接口规范保持一致或有明确映射说明。
- 数据为空时页面不报错，并有合理空状态或兜底展示。
- `npm run build` 可通过。

### 5.6 当前状态判断

当前项目已有 `src/data/site.js`，产品、案例、时间轴等部分内容已经数据化，但首页仍有大量内容硬编码在 `Home.vue` 中，且还没有独立 Mock 目录和统一字段规范落地。

因此第二阶段是当前最适合优先推进的阶段。

## 6. 第三阶段：API 层与表单能力

### 6.1 阶段目标

建立前端 API 层，让页面不直接依赖本地数据文件，为后续切换真实后端接口做准备。同时补齐联系我们表单的字段绑定、校验、提交、状态提示。

这一阶段完成后，前端应具备“本地 Mock 可用，真实接口可切换”的基础能力。

### 6.2 主要任务

- 新增 `src/api` 目录，按业务拆分接口模块。
- 新增 `src/utils/request.js`，封装基础请求能力。
- 新增环境变量：
  - `VITE_USE_MOCK=true`
  - `VITE_API_BASE_URL=http://localhost:8080`
- API 方法在 Mock 模式下返回本地数据，在真实接口模式下调用后端接口。
- 改造页面组件，使其通过 API 方法获取数据。
- 联系我们表单补齐字段绑定、必填校验、邮箱校验、电话基础校验。
- 联系我们表单补齐提交 loading、防重复提交、成功提示、失败提示。
- 提交字段与 `ContactLead` 接口字段保持一致。

### 6.3 建议目录

```text
src/
├── api/
│   ├── home.js
│   ├── products.js
│   ├── cases.js
│   ├── about.js
│   ├── contact.js
│   └── site.js
├── utils/
│   └── request.js
└── data/
```

### 6.4 交付物

- `src/api` 接口模块。
- `src/utils/request.js` 请求封装。
- `.env` 或 `.env.example` 环境变量说明。
- 可工作的 Mock/API 切换逻辑。
- 完整可交互的联系我们表单。
- 表单提交成功、失败、加载中状态。

### 6.5 验收标准

- `VITE_USE_MOCK=true` 时页面使用本地 Mock 数据。
- `VITE_USE_MOCK=false` 时页面会调用真实接口地址。
- 接口请求失败时页面不崩溃，并有错误兜底。
- 联系我们表单必填项未填写时有提示。
- 邮箱格式错误时有提示。
- 提交中按钮有 loading 或禁用状态，不能重复提交。
- 模拟提交成功后有成功提示。
- 模拟提交失败时有失败提示。
- 表单提交字段与 `docs/前端字段与接口规范说明书.md` 保持一致。
- `npm run build` 可通过。

### 6.6 当前状态判断

当前项目没有 `src/api`，没有 `src/utils/request.js`，也没有 API/Mock 切换能力。联系我们表单目前是静态 UI，尚未实现字段绑定、校验和提交。

第三阶段应在第二阶段主要数据结构稳定后推进。

## 7. 第四阶段：后端接口联调

### 7.1 阶段目标

在后端接口具备基础可用能力后，将前端从 Mock 数据逐步切换到真实接口，完成字段、状态、错误处理和页面展示联调。

这一阶段重点是减少前后端字段理解偏差，保证真实数据进入页面后仍能稳定展示。

### 7.2 主要任务

- 与后端确认接口路径、请求方式、请求参数和响应结构。
- 与后端确认字段命名、字段类型、必填规则、排序规则、上下架规则。
- 联调以下接口：
  - `GET /api/site/config`
  - `GET /api/home`
  - `GET /api/products`
  - `GET /api/products/:id`
  - `GET /api/cases`
  - `GET /api/cases/:id`
  - `GET /api/about`
  - `GET /api/contact/info`
  - `POST /api/contact`
- 将 Mock 数据中已验证的字段同步给后端，减少接口返工。
- 处理 loading、empty、error、fallback 状态。
- 确认图片资源路径、上传资源域名、跨域配置和部署路径。

### 7.3 交付物

- 与后端确认后的接口清单。
- 联调完成的 API 调用代码。
- 接口异常处理和空数据兜底。
- 真实接口模式下可运行的官网页面。
- 联调问题记录和字段差异记录。

### 7.4 验收标准

- 后端接口返回成功时，首页、产品、案例、关于我们、联系信息可以正常展示。
- 后端接口返回空数据时，页面有合理空状态。
- 后端接口异常或网络错误时，页面不崩溃。
- 联系表单可以提交到真实接口，并能处理成功和失败结果。
- 产品和案例数据支持排序、上下架、详情获取。
- 图片资源可以正常加载，加载失败有兜底。
- 前端不出现数据库账号、密码、RDS 地址等敏感信息。
- `VITE_USE_MOCK=false` 模式下 `npm run build` 可通过。

### 7.5 当前状态判断

当前后端接口尚未接入，因此第四阶段尚未开始。前端应先完成第二、三阶段，保证联调时页面侧已有稳定的数据结构和 API 访问入口。

## 8. 第五阶段：正式上线优化

### 8.1 阶段目标

完成正式上线前的 SEO、资源、配置、构建、部署和兼容性检查，保证官网可以作为公司正式网站发布。

### 8.2 主要任务

- 补齐首页、产品详情、案例详情的 title、description、keywords。
- 补齐 favicon、Open Graph 基础信息和图片 alt。
- 确认备案号、公司全称、地址、电话、邮箱等正式信息。
- 将外链图片替换为公司真实素材、静态资源或后台上传资源。
- 检查移动端真实设备或浏览器模拟器表现。
- 检查主流浏览器兼容性。
- 检查构建产物体积，必要时使用路由懒加载或代码分包。
- 检查部署路径、静态资源路径、刷新路由 404 问题。
- 确认线上接口地址和跨域策略。
- 建议新增独立 `docs/上线检查清单.md` 跟踪上线事项。

### 8.3 交付物

- 可正式部署的 `dist/` 构建产物。
- 完整 SEO 和站点基础信息。
- 替换后的正式图片资源。
- 上线检查清单。
- 部署说明或部署注意事项。

### 8.4 验收标准

- `npm run build` 可通过。
- `npm run preview` 或部署环境可正常访问。
- 首页、产品页、案例页刷新后不出现 404。
- favicon 正常显示。
- 页面 title 和 meta 信息正确。
- 备案号和联系方式为正式信息。
- 图片资源加载稳定，不依赖不确定外链。
- 移动端无明显布局错乱。
- 表单在生产环境可以正常提交或有明确可用的降级方案。

### 8.5 当前状态判断

当前项目已具备构建能力，但 SEO、备案号、正式联系方式、正式图片资源、上线部署检查仍需补齐。

第五阶段应在数据化、API 能力和核心联调完成后集中处理。

## 9. 当前项目建议推进顺序

结合当前代码状态，建议按以下顺序继续开发：

1. 新建 `src/data/home.js`，先抽离 `Home.vue` 中的首页运营内容。
2. 拆分或整理 `src/data/products.js`、`src/data/cases.js`、`src/data/about.js`。
3. 统一产品和案例字段，建立旧字段到新字段的映射。
4. 新建 `src/api`，让页面先通过 API 方法读取本地 Mock 数据。
5. 新建 `src/utils/request.js`，预留真实接口调用。
6. 改造联系我们表单，完成字段绑定、校验和模拟提交。
7. 恢复 `/product/:id` 和 `/case/:id` 单详情页能力。
8. 补齐 loading、empty、error 和图片加载失败兜底。
9. 补充基础 SEO、favicon、备案号、正式联系方式。
10. 与后端确认接口字段和路径后进入联调。

## 11. 前后端协作节点

### 11.1 前端先行确认

- 页面模块结构。
- Mock 数据字段。
- API 层返回给组件的字段格式。
- 表单提交字段。
- 空状态、错误状态和加载状态展示方式。

### 11.2 前后端共同确认

- 接口路径。
- 请求方式。
- 请求参数。
- 响应结构。
- 错误码。
- 字段类型。
- 排序和上下架规则。
- 图片资源规范。
- 线上域名、接口地址和部署路径。

### 11.3 后端完成后前端联调

- 将 `VITE_USE_MOCK` 切换为 `false`。
- 验证真实接口数据展示。
- 记录字段差异并在 API 层适配。
- 验证表单真实提交。
- 验证接口异常、空数据、图片失败等边界情况。

## 12. 阶段完成定义

一个阶段可以视为完成，需要同时满足：

- 该阶段主要任务已完成。
- 该阶段交付物已产生。
- 该阶段验收标准已通过。
- `npm run build` 可通过。
- 没有阻塞下一阶段的已知问题。

如果阶段中仍有非阻塞事项，应记录为后续 P1/P2 任务，不影响进入下一阶段。

## 13. 当前结论

当前项目不应继续只堆静态页面，而应从第二阶段开始，把首页内容、产品、案例、关于我们、联系信息逐步数据化。

短期最关键的开发目标是：

```text
Home.vue 硬编码抽离
-> Mock 数据文件拆分
-> API 层封装
-> 联系表单可用
-> 单产品/单案例详情恢复
```

完成以上内容后，项目就可以从“可展示的静态官网”推进到“可接后端、可维护内容的公司官网”。
